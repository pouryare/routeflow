# Avatars — Owner Uploads and Owner-Chosen Presets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use /long-haul-development.md to implement this plan task-by-task (disk-backed plan + journal, `/newtask` relay, review gates). For a plan small enough to finish in one session, /executing-plans.md is the simpler inline path. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an owner give every user a real photograph — by uploading one or by choosing one of a preset set — so no page in the app ever falls back to coloured initials.

**Architecture:** This is mostly a *write path*, not a rendering change. `users.avatar_url` already exists (added by `ALTER TABLE`), `components/meridian/Avatar.tsx` already prefers `src` and falls back to initials by design, and `PATCH /api/admin/users/[id]` already exists and is already gated to `OWNER_ROLES`. Nothing can ever set `avatar_url` today, which is why every avatar in the app is initials. This plan adds: accepting `avatar_url` in the existing PATCH, an upload endpoint that runs through the **existing** `sharp` pipeline, and an owner-only picker in the admin users screen.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, `sharp@0.33.5` (pinned exactly — see Notes), Vitest 4, SQLite via `node:sqlite`.

---

## The decision that shapes this: owner-only

**Nobody may set their own avatar.** The owner's stated reason is that staff would upload inappropriate images. That reason is recorded here so a later change does not quietly reopen it: if self-service is ever added, it needs a moderation queue, not a flip of the `OWNER_ROLES` gate.

`PATCH /api/admin/users/[id]` is already `requireRole(req, OWNER_ROLES)`, so this plan inherits the correct authorisation for free and must not weaken it.

## The image pipeline is already built — reuse it

`app/api/photos/route.ts` POST already does exactly the right thing:

```ts
const pipeline = sharp(inputBuffer)
  .rotate()
  .resize({ width: 1600, height: 1600, fit: "inside", withoutEnlargement: true });
[avifBuffer, webpBuffer] = await Promise.all([
  pipeline.clone().avif({ quality: 60 }).toBuffer(),
  pipeline.clone().webp({ quality: 78 }).toBuffer(),
]);
```

It encodes **both** AVIF and WebP and never writes the original. `PhotoGallery.tsx` and `app/(shell)/gallery/page.tsx` already render `<picture>` with an AVIF `<source>` and a WebP fallback.

**Correction worth knowing:** Firefox has supported AVIF since **v93** (Chrome 85, Safari 16.4, iOS 16.4; ~95% global). So both Chrome and Firefox receive AVIF and each picks the first `type` it can decode. There is no user-agent branching anywhere and none should be added — `<picture>` exists precisely because UA strings lie.

**The one real gap:** the five committed files in `public/avatars/` are raw originals served unprocessed. They are the only image surface in the app bypassing the pipeline.

```ts
/** One image encoder for the whole app.
 *
 *  `app/api/photos/route.ts` grew this inline and got it right: rotate (so a phone's EXIF
 *  orientation is honoured), cap the long edge, and emit BOTH AVIF and WebP. That last part
 *  is why this file exists. A browser picks the first `<source type>` it can decode, so
 *  emitting both is what lets Chrome and Firefox each receive AVIF while anything older
 *  still gets WebP — no user-agent branch, and there should never be one: UA strings lie.
 *
 *  Photos cap at 1600px and avatars at 512px: an avatar is displayed at most 96px in the
 *  briefing hero, so anything larger is bytes nobody will ever fetch.
 *
 *  THE ORIGINAL IS NEVER WRITTEN — not to disk, not temporarily. Encoding to two buffers
 *  and discarding the input means there is no window in which an unredacted original sits
 *  on disk, which for a photograph of a person is the difference between a privacy
 *  property and a hope.
 */

import sharp from "sharp";

/** Long edge, in px, for a district or customer photo. */
export const PHOTO_MAX_EDGE = 1600;
/** Long edge, in px, for a user avatar. */
export const AVATAR_MAX_EDGE = 512;

export interface EncodedImage {
  avif: Buffer;
  webp: Buffer;
}

/** AVIF q60 and WebP q78 are the values the photo route has shipped with. Do not retune
 *  them without re-encoding every existing file: a quality change only applies to files
 *  encoded after it, so a mixed corpus is inevitable and the cheaper of the two is the one
 *  to freeze. */
export async function encodeImage(input: Buffer, maxEdge: number): Promise<EncodedImage> {
  const pipeline = sharp(input)
    .rotate()
    .resize({ width: maxEdge, height: maxEdge, fit: "inside", withoutEnlargement: true });

  const [avif, webp] = await Promise.all([
    pipeline.clone().avif({ quality: 60 }).toBuffer(),
    pipeline.clone().webp({ quality: 78 }).toBuffer(),
  ]);

  return { avif, webp };
}
```

```ts
/** Where a person's photograph lives, and which canned ones exist.
 *
 *  Under `data/photos/avatars/`, NOT `public/`. `public/` is committed, so an upload
 *  written there is a real person's photograph in the next `git add -A` — and this app
 *  stores photographs of identifiable people who did not choose to be online.
 *  `data/photos` is already gitignored.
 *
 *  `ROUTEFLOW_AVATAR_DIR` exists so a test can point this at a tmp directory; it is read
 *  once at module load, exactly like `PHOTOS_DIR` in `lib/photos.ts`.
 */

import path from "node:path";
import fs from "node:fs/promises";

export const AVATAR_DIR =
  process.env.ROUTEFLOW_AVATAR_DIR ?? path.join(process.cwd(), "data", "photos", "avatars");

export type AvatarFormat = "avif" | "webp";

export interface AvatarPreset {
  /** Bare token, no separators. This is the only part that ever reaches the filesystem. */
  key: string;
  label_fa: string;
}

/** The five files already committed under `public/avatars/`, which nothing referenced. They
 *  were made for exactly this and never wired up. `scripts/seed-avatars.mjs` re-encodes
 *  them through the app's own pipeline, so a preset is the same bytes an upload would be. */
export const AVATAR_PRESETS: AvatarPreset[] = [
  { key: "hossein", label_fa: "حسین" },
  { key: "maryam", label_fa: "مریم" },
  { key: "reza", label_fa: "رضا" },
  { key: "saeed", label_fa: "سعید" },
  { key: "zahra", label_fa: "زهرا" },
];

/** `null` for anything that is not exactly one bare token. This is a security boundary, not
 *  a tidy-up: the key reaches a filesystem path, and `../../../etc/passwd` looks like a
 *  preset to every caller that forgot to check. Percent-encoding is refused too —
 *  `re%2Fza` survives one decode pass. */
export function safePresetKey(key: unknown): string | null {
  if (typeof key !== "string") return null;
  return /^[a-z0-9-]{1,40}$/.test(key) ? key : null;
}

export function avatarPaths(stem: string, format: AvatarFormat): string {
  return path.join(AVATAR_DIR, `${stem}.${format}`);
}

export async function ensureAvatarDir(): Promise<void> {
  await fs.mkdir(AVATAR_DIR, { recursive: true });
}

/** `null` rather than a throw: a missing avatar is the normal state for most users, and
 *  the renderer's answer is the initials fallback, not a 500. */
export async function readAvatarBytes(stem: string, format: AvatarFormat): Promise<Buffer | null> {
  try {
    return await fs.readFile(avatarPaths(stem, format));
  } catch {
    return null;
  }
}
```

```ts
import { NextRequest, NextResponse } from "next/server";
import crypto from "node:crypto";
import fs from "node:fs/promises";
import { encodeImage, AVATAR_MAX_EDGE } from "@/lib/imagePipeline";
import { ensureAvatarDir, avatarPaths } from "@/lib/avatarStore";
import { requireRole } from "@/lib/session";
import { getDb } from "@/lib/db";
import { OWNER_ROLES } from "@/lib/roles";

/** 8MB. A phone portrait is 2–4MB; a 20MB phone panorama is a mistake, not a portrait. */
const MAX_UPLOAD_BYTES = 8 * 1024 * 1024;

/** Owner-only, by decision: nobody sets their own face. The stated reason is that staff
 *  would upload inappropriate images, and the answer to that is a gate on the write, not a
 *  moderation queue nobody has staffed. `OWNER_ROLES` is the same gate every other
 *  administrative write in this app uses. */
export async function POST(req: NextRequest) {
  const guard = requireRole(req, OWNER_ROLES);
  if (!guard.ok) return guard.response;

  const formData = await req.formData().catch(() => null);
  const file = formData?.get("file");
  const userId = Number(formData?.get("user_id"));

  if (!file || !(file instanceof File)) {
    return NextResponse.json({ ok: false, error: "فایلی انتخاب نشده است" }, { status: 400 });
  }
  if (!file.type.startsWith("image/")) {
    return NextResponse.json({ ok: false, error: "فقط فایل تصویر پذیرفته می‌شود" }, { status: 400 });
  }
  if (file.size > MAX_UPLOAD_BYTES) {
    return NextResponse.json(
      { ok: false, error: "حجم فایل نباید بیش از ۸ مگابایت باشد" },
      { status: 413 },
    );
  }
  if (!Number.isInteger(userId)) {
    return NextResponse.json({ ok: false, error: "شناسه کاربر نامعتبر است" }, { status: 400 });
  }

  // Tenant-scoped, same rule as the admin PATCH: an owner administers their own
  // organisation's staff and no one else's. A cross-tenant id reads as "not found".
  const db = getDb();
  const exists = db
    .prepare("SELECT id FROM users WHERE id = ? AND organization_id = ?")
    .get(userId, guard.session.organizationId);
  if (!exists) {
    return NextResponse.json({ ok: false, error: "کاربر پیدا نشد" }, { status: 404 });
  }

  const input = Buffer.from(await file.arrayBuffer());
  let encoded;
  try {
    encoded = await encodeImage(input, AVATAR_MAX_EDGE);
  } catch {
    return NextResponse.json({ ok: false, error: "فایل تصویر قابل پردازش نیست" }, { status: 422 });
  }

  // A random stem, never the user id and never the username: the filename must not be
  // guessable from the row, and a username is often someone's name in Latin letters.
  const stem = crypto.randomUUID();
  await ensureAvatarDir();
  await Promise.all([
    fs.writeFile(avatarPaths(stem, "avif"), encoded.avif),
    fs.writeFile(avatarPaths(stem, "webp"), encoded.webp),
  ]);

  // The row is written here rather than by a second client PATCH: one request, one outcome,
  // and no window in which the bytes exist but nothing points at them.
  db.prepare("UPDATE users SET avatar_url = ?, avatar_stem = ? WHERE id = ?").run(
    `/api/users/${userId}/avatar`,
    stem,
    userId,
  );

  return NextResponse.json({ ok: true, avatar_url: `/api/users/${userId}/avatar` });
}
```

Create `app/api/users/[id]/avatar/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";
import { getDb } from "@/lib/db";
import { getSession } from "@/lib/session";
import { AVATAR_PRESETS, readAvatarBytes, safePresetKey } from "@/lib/avatarStore";

/** The encoded bytes for one person's avatar.
 *
 *  Authenticated-but-not-privileged on purpose. `/driver` shows a colleague's face on the
 *  route screen, so a MANAGE_ROLES gate here would blank every avatar in the vehicle app —
 *  the one surface where recognising the person in front of you matters most. There is no
 *  private photograph here: it is the same face the app's own people lists already show,
 *  and a login is required to ask at all.
 *
 *  `?key=<preset>` serves one of the canned portraits; without it the user's own
 *  `avatar_stem` is used. `?format=avif` returns AVIF and anything else WebP, which is what
 *  a `<picture>` fallback chain expects. */
export async function GET(req: NextRequest, ctx: RouteContext<"/api/users/[id]/avatar">) {
  if (!getSession(req)) {
    return NextResponse.json({ ok: false, error: "احراز هویت نشده" }, { status: 401 });
  }

  const { id } = await ctx.params;
  const userId = Number(id);
  if (!Number.isInteger(userId)) {
    return NextResponse.json({ ok: false, error: "شناسه نامعتبر" }, { status: 400 });
  }

  const q = new URL(req.url).searchParams;
  const format = q.get("format") === "avif" ? "avif" : "webp";

  const row = getDb().prepare("SELECT avatar_stem FROM users WHERE id = ?").get(userId) as
    | { avatar_stem: string | null }
    | undefined;
  if (!row) {
    return NextResponse.json({ ok: false, error: "عکس پیدا نشد" }, { status: 404 });
  }

  // safePresetKey is the boundary: a key reaches a filesystem path, so "../../etc/passwd"
  // must be refused here rather than trusted because a caller "only ever passes presets".
  const presetKey = q.has("key") ? safePresetKey(q.get("key")) : null;
  if (q.has("key") && (!presetKey || !AVATAR_PRESETS.some((p) => p.key === presetKey))) {
    return NextResponse.json({ ok: false, error: "عکس پیدا نشد" }, { status: 404 });
  }

  const stem = presetKey ?? row.avatar_stem;
  if (!stem) {
    return NextResponse.json({ ok: false, error: "عکس پیدا نشد" }, { status: 404 });
  }

  const bytes = await readAvatarBytes(stem, format);
  if (!bytes) {
    return NextResponse.json({ ok: false, error: "عکس پیدا نشد" }, { status: 404 });
  }

  return new NextResponse(new Uint8Array(bytes), {
    headers: {
      "Content-Type": format === "avif" ? "image/avif" : "image/webp",
      "Cache-Control": "private, max-age=3600",
    },
  });
}
```
