# Icon Rule and Icon-on-Every-Button Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use /long-haul-development.md to implement this plan task-by-task (disk-backed plan + journal, `/newtask` relay, review gates). For a plan small enough to finish in one session, /executing-plans.md is the simpler inline path. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Lucide the one documented icon library in `MASTER.md`, add a guard test that fails on a direct `lucide-react` import or an emoji used as an icon, and give every action button an icon.

**Architecture:** `components/meridian/icon-map.ts` already curates ~100 icon names behind one `ICONS` object, and `components/meridian/Icon.tsx` is the only sanctioned renderer. The gap is that `MASTER.md` line ~720 says Lucide and Feather "are excluded" and names Phosphor as the candidate — the file contradicts the shipped code. This plan replaces that line with a real rule and adds `tests/icon-rule.test.ts`, which enforces the rule mechanically so it cannot rot.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, `lucide-react@1.43.0`, Tailwind CSS v4, Vitest 4.

- [ ] **Step 1: Write the test file header and helpers**

Create `tests/icon-rule.test.ts` with this content:

```ts
import { describe, it, expect } from "vitest";
import { readFileSync, readdirSync, statSync } from "node:fs";
import path from "node:path";

const root = path.resolve(__dirname, "..");
const read = (p: string) => readFileSync(path.join(root, p), "utf8");

function walk(dir: string): string[] {
  return readdirSync(path.join(root, dir)).flatMap((name) => {
    const rel = path.join(dir, name);
    if (statSync(path.join(root, rel)).isDirectory()) return walk(rel);
    return rel.endsWith(".tsx") || rel.endsWith(".ts") ? [rel] : [];
  });
}

/** The only files allowed to name the icon library directly. Everything else goes through
 *  `components/meridian/Icon`, which keeps stroke width and pixel size from drifting
 *  apart between two buttons that mean the same thing. */
const SANCTIONED = new Set([
  path.join("components", "meridian", "icon-map.ts"),
  path.join("components", "meridian", "Icon.tsx"),
  path.join("tests", "icon-rule.test.ts"),
]);

/** Emoji in the ranges most likely to be pasted "as an icon". */
const EMOJI =
  /[\u{1F300}-\u{1FAFF}\u{2600}-\u{27BF}\u{FE0F}\u{2190}-\u{21FF}\u{2B00}-\u{2BFF}]/u;

/** Comments are stripped before the emoji scan: a comment explaining WHY emoji are banned
 *  must be able to name one. */
function stripComments(src: string): string {
  return src.replace(/\/\*[\s\S]*?\*\//g, "").replace(/(^|[^:])\/\/.*$/gm, "$1");
}
```

- [ ] **Step 2: Append the five test cases**

Append to the same file:

```ts
describe("one icon library, reached one way", () => {
  it("finds the files at all (guards the walker itself)", () => {
    const files = [...walk("app"), ...walk("components")];
    expect(files.length).toBeGreaterThan(100);
    expect(files).toContain(path.join("components", "meridian", "Icon.tsx"));
  });

  it("no feature file imports lucide-react directly", () => {
    const offenders: string[] = [];
    for (const f of [...walk("app"), ...walk("components")]) {
      if (SANCTIONED.has(f)) continue;
      if (/from\s+["']lucide-react["']/.test(read(f))) offenders.push(f);
    }
    expect(
      offenders,
      `import { Icon } from "@/components/meridian/Icon" instead:\n${offenders.join("\n")}`,
    ).toEqual([]);
  });

  it("no emoji is used as an icon", () => {
    const offenders: string[] = [];
    for (const f of [...walk("app"), ...walk("components")]) {
      const src = read(f);
      for (const m of stripComments(src).matchAll(EMOJI)) {
        const line = src.slice(0, m.index).split("\n").length;
        offenders.push(`${f}:${line}  ${JSON.stringify(m[0])}`);
      }
    }
    expect(offenders, `use <Icon name="…" />:\n${offenders.join("\n")}`).toEqual([]);
  });

  it("MASTER.md names Lucide as the one library", () => {
    expect(read("MASTER.md")).toMatch(/##\s*Icon\b[\s\S]*?lucide/i);
  });

  it("MASTER.md no longer excludes Lucide", () => {
    expect(read("MASTER.md")).not.toMatch(/lucide[^.\n]{0,80}excluded/i);
  });
});
```

```markdown
## Icons `SHIPPED` — one library, reached one way

**Lucide, and only Lucide.** Every glyph comes from `lucide-react` through
`components/meridian/icon-map.ts` and is rendered by `components/meridian/Icon`. This
file used to say the opposite, so the reason is worth stating:

**Lucide is stroke-only and monochrome.** Every glyph is an outline that inherits
`currentColor` and takes its colour from CSS. That is exactly the rule this file already
states for icons, so Lucide complies with the system rather than negotiating with it.
Phosphor — the alternative considered — is defined by its duotone and fill weights, which
would either have broken the monochrome rule in several places, or meant using only its
thin outline set, which is what Lucide already is. Settled, and not to be reopened by a
later redesign.

**The rules.**

- **Never import `lucide-react` in a feature file.** Add a name to `ICONS` in
  `icon-map.ts`, render it with `<Icon>`. A direct import is how stroke width and pixel
  size drift back in, which is the entire reason the wrapper exists.
- **Every action button carries an icon.** Icon first, then the label, reading
  right-to-left in this RTL app.
- **Icon + label on anything whose meaning is not obvious from the glyph.** Add, delete,
  edit, print, export, filter — these get both.
- **Icon-only only where a label genuinely will not fit**, and never without an
  accessible name: `<Icon name="trash" label="حذف" />`. An icon-only button with no
  `label` is invisible to a screen reader.
- **Size is a token, never raw pixels.** `sm` / `md` / `lg` from `IconSize`.
- **`filled` is a state, not a colour knob.** It marks an on/off glyph (a rated star, a
  pinned marker). The icon stays one ink either way.
- **No emoji as an icon, ever.** An emoji is a coloured picture from a font you do not
  control: it renders in the vendor's palette (Apple's 🔔 is amber, Noto's is brown),
  ignores `color`, ignores stroke weight, and changes shape between the reader's phone and
  their desktop. One emoji in a panel is enough to make an otherwise monochrome interface
  look assembled from parts.

`tests/icon-rule.test.ts` enforces the first and last of these mechanically and fails on a
stale `MASTER.md`, so a glyph added straight to a feature file fails the suite the day it
lands.
```

Read the list and sort it:

- **Bucket 1 — real actions:** add, delete, edit, save, cancel, filter, export, print, refresh, search, open, close, next, previous, assign, upload, print receipt. **These all get an icon.**
- **Bucket 2 — navigation and layout:** a tab, a view toggle, a card that is itself a link, a chip. **Icon only if the glyph is unambiguous.** A toggle whose state is carried by colour must not also carry an ambiguous glyph.

- [ ] **Step 2: For each Bucket-1 button, add the icon**

```tsx
<button
  type="button"
  onClick={onAdd}
  className="inline-flex items-center gap-[var(--space-2)] …"
>
  <Icon name="plus" size="sm" />
  <span>افزودن</span>
</button>
```

Three rules that matter:

- `inline-flex items-center gap-[var(--space-2)]` **on the button**. Without `inline-flex` the icon and label sit on separate lines and the button grows to two rows.
- `size="sm"` beside `--text-sm` text, `size="md"` beside `--text-base`.
- If the button has **no** visible label, add one: `label="حذف"`.
