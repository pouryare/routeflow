# RouteFlow audit — 2026-10-20

Scope: every page under `app/(shell)` and `app/(bare)`, every route under `app/api`, 7 demo roles (platform_owner, owner, group_manager, rep_manager, phone_sales, field_rep, delivery_driver) plus two second-tenant managers. Method: Playwright crawl of all 55 routes × 7 roles (desktop, production build) + mobile 390px on 12 key routes × 3 roles, axe-core WCAG A/AA scan, a 221-endpoint × 8-identity API matrix, tenant-isolation (IDOR) probes, input-validation probes, login/logout flows, click-fuzzing, `tsc`, `eslint`, `npm audit`, `vitest` (3698 pass; 2 fail only because of temporary patches / no browser path), manual security read of auth, proxy, uploads, SSRF guards. Nothing was fixed; this is a list only.

Code-audit skill: none exists in the claude.ai skill catalogue. A web search only turned up third-party *skill-safety* auditors (they audit other skills, not application code), and installing unreviewed third-party skills is a supply-chain risk, so none was installed. Used the built-in `security-review`/`code-review` approach, `semgrep` (could not run: Python dependency conflict in this container), `npm audit`, `eslint`, `tsc`, and manual review.

## Part 1 — What the app is for, and how the pages connect

RouteFlow (Persian/RTL, Jalali dates) is an order-to-cash + field-sales + delivery + light-accounting system for a dairy-style distributor in Tehran. SQLite, multi-tenant (organisations → groups), 7 roles.

**Shell layout** (top nav → per-section tabs): روز من · مشتریان · فروش و دریافت · تحویل و انبار · گزارش‌ها · حسابداری · تیم · تنظیمات سازمان. **Bare layout**: `/driver`, `/today`, `/login`, `/offline` — no chrome (phone in a van).

| Area | Pages | Purpose → interacts with |
|---|---|---|
| Entry | `/` | Redirect router: van roles → `/driver`, everyone else → `/sales/today`. `/login` signs in (`/api/login`, rate-limited), `/offline` is the service-worker fallback. |
| My day | `/sales/today`, `/today`, `/sales/pocket`, `/sales/tasks`, `/sales/schedule`, `/sales/academy` | Daily briefing (tasks, orders waiting, alerts) fed by tasks/alerts/rules sweeps; Pocket = my tasks; Tasks board + recurrences = manager tool; Schedule = month calendar of visits and delivery runs, runs view assigns confirmed orders to drivers (feeds `/driver`); Academy = objection scripts/lessons. |
| Customers (CRM) | `/crm`, `/crm/[id]`, `/leads`, `/map`, `/planner`, `/facilities`, `/gallery` | `/leads` = unvetted map pins → added to lists → become CRM leads (`/crm`); a lead becomes a customer on first order (`promoteLeadToCustomer`). `/map` = coverage map of districts/customers/facilities (layers, pins, search); `/planner` = day route planning, hands to navigation app; `/facilities` = warehouses/depots (route origins); `/gallery` = photos of customers/districts. Lead runs from `/leads` appear on the driver's `/driver`. |
| Sales & receipts | `/sales` (overview), `/sales/dashboard` (analysis), `/sales/analysis`, `/sales/orders` (+ board/journey views), `/sales/orders/new`, `/sales/orders/[id]`, `/sales/products`, `/sales/payments`, `/sales/cheques`, `/sales/commission`, `/sales/complaints`, `/sales/forecast` | Orders move DRAFT→submitted→CONFIRMED→PLANNED→delivered→paid via the order state machine; confirming reserves stock; delivery completes on `/driver`; payments allocate to orders and post to the ledger; cheques have a deposit/bounce lifecycle; commission is computed from delivered orders; complaints trace to production batches; forecast/churn come from the predict sweeps. |
| Delivery & stock | `/sales/routing`, `/sales/runs`, `/sales/deliveries` (the last two redirect), `/sales/batches`, `/sales/stock`, `/driver` | Routing builds runs from templates/vehicles/weather/capacity → runs shown in schedule → driver executes stops (deliver/fail/unload, collect payment, record lead visits) via an offline-first outbox (`/api/sync/*`) → failed deliveries return orders to the plannable pool. Batches/stock track production lots, expiry, movements. |
| Accounting (owner) | `/accounting/trial-balance, journal, ledger/[id], balance-sheet, income-statement, payables, suppliers(+/[id]), expenses` | Double-entry ledger fed by orders, payments, purchases, expenses; reports are derived, voids are reversing entries. |
| Team / admin (owner) | `/sales/reps`, `/sales/reps/[id]`, `/sales/admin/users`, `/groups`, `/holidays`, `/representatives`, `/switch` | Representatives onboarding & health, user CRUD, territory groups, holiday calendar, impersonation (login-as, with return banner). |
| Reports | `/report`, `/analytics` | Group-wide coverage/debt report with CSV; lead analytics. |
| Settings | `/settings/notifications` | Per-type opt-ins, quiet hours, push/Telegram linking. |

Role gating: proxy.ts (coarse, claims-based) → page redirects → API `requireRole` + group/org scoping (404-not-403 for foreign rows). Van roles are confined to `/driver`, `/today`, academy, settings, notifications, tasks, driver visits, sync.

## Part 2 — Problems found (list only)

Severity: **C** critical, **H** high, **M** medium, **L** low.

### Build / availability
1. **C** `next build` fails: `app/(shell)/sales/admin/holidays/page.tsx` is `"use client"` but imports server component `components/meridian/PageHeader.tsx` (uses `next/headers`). In dev the page 500s.
2. **C** Driver app breaks the bundle: `components/driver/UnloadTapFlow.tsx` value-imports `DISPOSITIONS`/`DISPOSITION_LABEL` from `lib/repo/unload.ts` → `lib/db` → `node:sqlite` in the browser chunk. Build fails on `/(bare)/driver/page`; dev `/driver` returns 500 for delivery_driver, field_rep and platform_owner and cascades Turbopack write errors onto other routes.
3. **H** `/report` throws for role `owner`: `groupFilter()` (`lib/session.ts:185-190`) emits `organization_id = ?` but `districts` has no such column (`report/page.tsx:64`).
4. **H** `/sales/schedule?view=runs` (and alias `/sales/runs`) crashes for owner, group_manager and rep_manager: `PLANNABLE_SQL` (`lib/repo/dayPlan.ts:50-125`) never interpolates `scope.sql` yet binds `scope.params` ("column index out of range"). For roles with no params the tenant/group scope is silently not applied (cross-tenant order leak risk).
5. **M** `lib/avatarStore.ts:47,58` dynamic fs access makes Turbopack trace the whole project into the avatar route.
6. **M** React "unique key" warning in IncomeStatement `<tbody>`.
7. **M** After the bad rows from items 12–14 exist, `/api/sales/customers/[id]/summary` and `POST /api/predict/refresh` return 500 and `/accounting/balance-sheet` shows the error boundary — bad input propagates into reports.

### Security
8. **H** Open redirect after login: `login/page.tsx:25-54` does `router.push(?next=…)` unvalidated. Verified `?next=https://evil.example/x` and `?next=//evil.example/x` leave the site.
9. **H** Login rate limit trusts client `x-forwarded-for` (first value) → bypass by rotating the header (verified: 8 different values never throttled). Without the header all clients share key `"unknown"`, so 5 bad logins from anyone lock everyone out for 15 min (observed).
10. **M** `GET /api/payments` returns the whole organisation's payments (576 rows incl. customer, amount, receiver) to `phone_sales`, byte-identical to the owner payload; `/api/tasks` and `/api/alerts` likewise unscoped for sales.
11. **L** SSRF guard on map-link resolution checks the allow-list only for the first hop; redirect hops are only checked against private/local hosts (`lib/resolveMapsLink.ts:185`, `app/api/geo/decode-link`).

### Data validation / integrity
12. **C** `POST /api/sales/orders` does no line validation: `packs` = 0, −3, 1.5, `"5"`, `null`, `1e12` all return 201. Negative/fractional/huge quantities flow into totals, stock reservation, commission and the ledger.
13. **H** Same endpoint accepts `order_date` 2999-01-01 (created order number `2377-00001`, polluting numbering), `salesperson_user_id` of a user in **another tenant** and of a driver, `notes` as an object and a 200 KB string, 100 duplicate lines.
14. **C** `POST /api/payments` has no upper bound: 9007199254740993 is accepted; afterwards `GET /api/payments` and every payment/ledger aggregation throws `RangeError: Value is too large to be represented as a JavaScript number` (56+ server errors) — one bad row bricks `/sales/payments`. Also `received_at: "not-a-date"` → 500 with empty body; future dates accepted.
15. **L** Illegal order transition message exposes raw state code («DRAFT») inside Persian text; several 404s (e.g. `GET /api/sales/orders/[id]` for another role) return an empty body instead of the JSON error shape.

### Roles / permissions consistency
16. **H** `platform_owner` ("strict superset of owner") is redirected to `/sales` from `/sales/admin/*`, `/sales/batches`, `/sales/cheques`, `/sales/forecast`, `/sales/routing`, `/sales/reps(+/[id])` because pages hard-code `role !== "owner" && role !== "group_manager"` (≈88 literal `"owner"` comparisons remain) instead of `OWNER_ROLES`/`MANAGE_ROLES`, while the proxy/API allow it. Also gets 403 on `POST /api/analysis/refresh`, `/api/predict/refresh`, `/api/rules/run`, `/api/sync/*` and order transitions.
17. **H** Van roles cannot log out: `/driver` «خروج» posts to `/api/logout`, which proxy.ts 403s for van roles; the user lands on a bare JSON page and the cookie is not cleared. `/api/me` and `/api/prefs` (used by `useSession`) are also 403 for them.
18. **M** rep_manager can open `/leads`, `/facilities`, `/gallery`, `/map`, `/planner`, `/analytics`, `/sales/complaints`, `/sales/payments` but their APIs (`/api/locations`, `/api/facilities`, `/api/photos`, `/api/districts/geometry`, `/api/lead-lists`, `/api/lead-runs`, `/api/customers`, `/api/payments`, `/api/sales/complaints`…) answer 403 → blank/broken pages.
19. **M** phone_sales can open `/facilities`, `/gallery`, `/map`, `/planner` (in nav) but `/api/facilities`, `/api/photos`, `/api/districts/geometry`, `/api/visit-plans`, `/api/reminders`, `/api/locations`, `/api/customers`, `/api/activity` are 403.
20. **M** Deactivating a user is a single click with no confirmation (automated clicking deactivated `demo.driver`; login then 401).
21. **L** A signed-in user opening `/login` is not redirected away.
22. **L** Unknown-ID pages (`/sales/orders/[id]`, `/crm/[id]` for foreign rows) render the not-found UI with HTTP 200 (soft 404).

### Visual / accessibility
23. **M** Colour contrast fails on every page (19–286 nodes; worst `/sales/orders` redirect targets 286, `/sales/forecast` 163, `/sales/stock` 136): inactive sub-tabs, `<kbd>`, `<bdi>` use `#79818e` on `#fff` = 3.92:1; avatar initials `#9a6b10` on `#fbf1dd` = 4.17:1. `#79818e` is not a MASTER.md token; `check:contrast` passes while the live pages do not (token drift).
24. **M** Unlabelled controls: `.stsort` select on `/sales/stock`; per-row selects on `/sales/admin/users` (16), groups, facilities, batches, cheques, complaints; 20 unlabeled inputs on `/leads`; 24 icon-only buttons/links without names on `/sales/dashboard`; Leaflet markers with role=button and no name on `/leads`, `/map`, `/analytics` (20–37).
25. **M** `aria-hidden` sheet contains focusable controls on `/crm`, `/sales/orders`, `/sales/pocket`, `/sales/tasks`, `/sales/deliveries`.
26. **M** CSP `img-src` lists `https://tile.openstreetmap.org` but OSM tiles load from `a/b/c.tile.openstreetmap.org` → tiles blocked on `/analytics` (`next.config.ts`).
27. **L** Geolocation permission is requested/warned on every page including `/login` and `/offline` (`MyPositionProvider`).
28. **L** For `phone_sales`, `/planner` highlights an empty slot in the top nav (white blank pill) and has no section tabs; `/sales/orders` first paint shows a washed-out translucent panel overlapping cards until the entrance animation ends (~1.2 s+); "امروز" and the date are repeated on `/sales/today`; driver «خروج» button has very low contrast.
29. **L** Mobile (390 px, 12 routes × 3 roles): no horizontal overflow found; same contrast/label issues as desktop. `/sales/payments` throws an uncaught `SyntaxError: Unexpected end of JSON input` when the API 500s (no error handling on `res.json()`).

### Dependencies / tooling
30. **H** `npm audit`: 1 critical (maplibre-gl), 12 high (next, undici, sharp, @xmldom/xmldom, js-yaml, brace-expansion, source-map-js, braces/micromatch/fast-glob via eslint-config-next), 2 moderate (vitest).
31. **L** `tsc` fails until `next typegen` is run (`RouteContext`/`LayoutProps` undefined) — fresh clones/CI need the step; eslint: 1 warning (`useMemo` unused).
32. **L** `tests/playwrightExtract.test.ts` fails where Playwright's default Chromium path is absent; `tests/shell-pages-have-tabs.test.ts` correctly catches item 1 only once the page is patched.

### Round 2 — extended click/form testing (added)
33. **C** Verified through the real UI as phone_sales: `/sales/orders/new` accepts quantities −3, 1.5 and 99999999999 and creates orders (201). Persian digits (۵) typed into the quantity field are not accepted, so users cannot type numbers naturally (inconsistent: the price form accepts them).
34. **H** The payment form silently rewrites input: "-5" → 5, "1000.5" → 10005 (decimal dropped, ×10), "' OR 1=1; --" → 11, a 25-digit entry → 1e25 (float). No validation message. The 1e25 row then breaks `GET /api/payments` (500, uncaught JSON error on the page) and `/sales/orders/new` for phone_sales (RangeError error boundary).
35. **H** Commission rate (1e25/kg) and commission payment (1e25) accepted; rows created via the UI have `organization_id = NULL` (orphaned from tenant scoping).
36. **M** Create-user / group / product forms accept any text: usernames like `"><img src=x onerror=alert("XSS")>`, 25-digit and 5000-char values (users created as role owner), 5000-char group/product names, duplicate group names, kg_per_base_unit 0 or 1e25, price 9999999999999999999999999. No XSS executed (React escapes) but data is unvalidated.
37. **M** Complaint form saves with an empty description; cheque and batch forms accept negative/25-digit/decimal numbers with no message.
38. **H** `POST /api/driver/stops/[id]` accepts "deliver" again on an already-delivered stop in a run with status done (200) and `collected_toman` 1e16 (no cap versus the order/outstanding balance) → double-recording / inflated cash.
39. **H** Destructive actions have no confirmation: «لغو سفارش» cancels an order on one click with no reason prompt; «حذف» on `/facilities` fires DELETE immediately; deactivating a user is one click (an automated click locked out the demo driver).
40. **L** The notification-bell popover on every shell page renders ~65px wide, wrapping «اعلان تازه‌ای ندارید.» onto three lines, and stays open when the profile button is clicked (profile menu does not appear).
41. **L** Verified working (no defects): global search (Ctrl K) for customers/orders/phone, order state transitions in the UI (confirm → plan → back), XSS payloads rendered as text everywhere tested, tenant isolation on all probed read APIs, driver stop edits scoped to the assigned driver (other field rep → 404, owner → 403), negative/NaN/over-ordered packs rejected on driver stops.
